## 1. 프런트엔드 (Frontend) — HTML·CSS·JavaScript

**비유**: 집 짓기
- **HTML** = 뼈대와 방 배치 (여기에 제목, 여기에 버튼)
- **CSS** = 벽지와 가구 배치 (글자 크기, 색, 간격)
- **JavaScript** = 전기와 수도 (버튼을 누르면 다음 카드가 나오는 동작)

**현장어에서**
```html
<h1>현장어</h1>
<div class="card">
  <h2>OAuth</h2>
  <p>비밀번호를 주지 않고 권한만 빌려주는 표준 승인 방식</p>
  <button id="next">다음 카드</button>
</div>
```
- `<h1>`, `<div>`, `<button>` 같은 것을 **태그(Tag)**라고 한다.
- `class="card"`는 CSS가 "이 상자를 카드 모양으로 꾸며라"라고 찾아가는 이름표다.

**직접 할 일**: 글자 크기와 색 바꾸기, 버튼 문구 바꾸기
**난이도**: ★★☆☆☆ (눈으로 결과를 바로 볼 수 있어서 가장 배우기 쉽다)
**면접 한 문장**: "화면은 HTML·CSS·JavaScript로 직접 만들어 프레임워크 없이도 웹이 동작하는 원리를 익혔습니다."
**함께 알면 좋은 용어**: DOM(Document Object Model: 브라우저가 HTML을 나무 구조로 기억하는 방식), 이벤트(Event: 클릭 같은 사용자 행동), 반응형 디자인(Responsive Design: 휴대폰·PC 화면 크기에 맞춰 바뀌는 디자인)

## 2. 데이터 모델링과 스키마 (Data Modeling / Schema) — glossary.json

**비유**: 이력서 양식
- 모든 지원자가 같은 칸(이름, 학력, 경력)을 채워야 비교하기 쉽다.
- **스키마** = 그 양식. "용어 카드는 반드시 이 칸들을 가진다"는 규칙.
- **데이터 모델링** = 어떤 칸이 필요한지 정하는 일.

**현장어에서**
```json
{
  "id": "oauth",
  "term_en": "OAuth",
  "term_ko": "오어스",
  "definition": "비밀번호를 주지 않고 권한만 빌려주는 표준 승인 방식",
  "examples": [
    { "context": "업무 회의", "sentence": "네이버 연동은 OAuth로 붙이면 고객 비밀번호를 저희가 보관할 필요가 없습니다." },
    { "context": "면접 답변", "sentence": "계정 연동은 OAuth로 처리해 앱이 비밀번호를 저장하지 않게 설계했습니다." }
  ],
  "tags": ["보안", "인증"]
}
```
- **JSON(JavaScript Object Notation)** = 컴퓨터끼리 데이터를 주고받는 가장 흔한 글자 형식.
- `{ }`는 하나의 묶음(객체, Object), `[ ]`는 목록(배열, Array).

**직접 할 일**: 용어 카드 하나를 JSON으로 직접 써 보기, 칸 하나 추가해 보기
**난이도**: ★★☆☆☆
**면접 한 문장**: "예문을 상황별로 저장하도록 스키마를 설계해, 화면과 음성 모드가 같은 데이터를 쓰게 했습니다."
**함께 알면 좋은 용어**: 필드(Field: 칸 하나), 유효성 검사(Validation: 규칙에 맞는지 확인)

## 3. 상태 관리 (State Management) — 복습 기록 저장

**비유**: 책갈피
- 책을 덮었다 다시 펴도 어디까지 읽었는지 기억해야 한다.
- **상태(State)** = 지금 앱이 기억하고 있는 정보. (이 카드는 3번 상자, 다음 복습은 11/15)
- **상태 관리** = 그 정보를 언제 바꾸고, 어디에 저장하고, 어떻게 다시 불러올지 정하는 일.

**현장어에서**
```javascript
// 저장하기
localStorage.setItem("review-oauth", JSON.stringify({ box: 3, next: "2026-11-15" }));
// 불러오기
const saved = JSON.parse(localStorage.getItem("review-oauth"));
```
- **localStorage** = 브라우저 안의 작은 서랍. 사이트를 닫았다 열어도 남아 있다.
- 서랍은 **기기마다 따로**다. 휴대폰 기록과 노트북 기록은 합쳐지지 않는다. (ADR-0001의 감수하는 점)

**직접 할 일**: 브라우저 개발자 도구(F12)에서 저장된 값 눈으로 확인하기
**난이도**: ★★★☆☆
**면접 한 문장**: "로그인 없이 복습 기록을 브라우저에 저장해 개인정보를 받지 않으면서 학습 상태를 유지했습니다."

## 4. 관심사 분리 (Separation of Concerns) — 공개 사이트와 LLM 작업 나누기

**비유**: 식당의 주방과 홀
- 손님(수강생)은 홀에서 완성된 음식만 받는다.
- 요리(LLM 처리, 검토)는 주방(내 컴퓨터)에서 한다.
- 주방 사정이 바뀌어도 홀은 그대로다. 각자 맡은 일만 한다.

**현장어에서**
```
field-words/
├── pipeline/   ← 주방: Python, LLM, 내 컴퓨터에서만 실행
└── site/       ← 홀: HTML·CSS·JS, 인터넷에 공개
```
- 둘을 잇는 것은 **glossary.json 하나뿐**이다. 이 연결 지점을 **인터페이스(Interface)** 또는 **계약(Contract)**이라고 한다.

**직접 할 일**: 폴더 구조를 보고 "이 파일은 주방인가 홀인가" 말해 보기
**난이도**: ★★☆☆☆ (개념은 쉽고, 중요도는 매우 높다)
**면접 한 문장**: "LLM 처리와 공개 화면을 분리하고 JSON 하나로만 연결해, 한쪽을 바꿔도 다른 쪽이 영향받지 않게 했습니다."

## 5. 비밀 관리 (Secret Management) — API 키 지키기

**비유**: 신용카드
- **API 키** = LLM을 쓸 때마다 요금이 청구되는 카드 번호.
- 공개 사이트에 넣으면 누구나 그 번호로 결제할 수 있게 된다.

**현장어에서**
- 키는 내 컴퓨터의 `.env` 파일에만 둔다. (**환경 변수, Environment Variable**: 코드 밖에 따로 보관하는 설정값)
- `.gitignore`에 `.env`를 적어 **GitHub에 절대 올라가지 않게** 한다.
- 공개 사이트에는 키가 아예 없다. 그래서 새어 나갈 수도 없다.

```
# .gitignore
.env
research/
```

**직접 할 일**: `.gitignore`가 무엇을 막는지 직접 확인하기 (`git status`로 보기)
**난이도**: ★★☆☆☆ (어렵지 않지만, 한 번 실수하면 피해가 크다)
**면접 한 문장**: "API 키는 공개 영역에 두지 않는 구조로 설계해, 키 유출 가능성을 원천적으로 없앴습니다."

## 6. CI/CD — 자동 배포

**비유**: 자동 인쇄소
- 원고(코드)를 우편함(GitHub)에 넣으면, 인쇄소가 알아서 검사하고 인쇄해서 서점(웹사이트)에 진열한다.
- **CI(Continuous Integration, 지속적 통합)** = 올릴 때마다 자동으로 검사.
- **CD(Continuous Deployment, 지속적 배포)** = 검사를 통과하면 자동으로 공개.

**현장어에서**
1. 내가 `git push` (코드를 GitHub에 올리기)
2. **GitHub Actions**가 자동 실행: glossary.json이 스키마에 맞는지 검사
3. 통과하면 **GitHub Pages**에 사이트 자동 공개

**직접 할 일**: 일부러 JSON에 실수를 넣고 push → 검사가 실패하는 것을 눈으로 보기
**난이도**: ★★★☆☆ (처음 설정만 어렵고, 그 뒤로는 자동)
**면접 한 문장**: "GitHub Actions로 데이터 검사와 배포를 자동화해, 잘못된 용어 데이터가 공개되지 않게 했습니다."
**함께 알면 좋은 용어**: 파이프라인(Pipeline: 순서대로 이어진 자동 작업), 워크플로(Workflow: GitHub Actions의 작업 설정 파일)

## 7. ETL — Python으로 LLM 처리

**비유**: 김장
- **Extract(뽑기)** = 밭에서 배추 뽑기 → 강의 메모·대화 기록에서 글 가져오기
- **Transform(바꾸기)** = 절이고 양념하기 → LLM이 용어를 찾고 뜻·예문을 만들기, 내가 검토하기
- **Load(싣기)** = 김치통에 담기 → glossary.json에 저장

**현장어에서**
```
강의 메모.txt
  → [Extract] 글 읽기
  → [Transform] LLM: "이 글에서 실무 용어를 찾아 JSON으로 정리해 줘"
  → [사람 검토] 맞는 것만 승인
  → [Load] glossary.json에 추가
```
- LLM에게 보내는 지시문을 **프롬프트(Prompt)**라고 한다. 원하는 형식(JSON)으로 답하게 만드는 것이 핵심 기술이다.

**직접 할 일**: 프롬프트 문장을 바꿔 보고 결과가 어떻게 달라지는지 비교하기
**난이도**: ★★★☆☆
**면접 한 문장**: "강의 메모에서 용어를 뽑는 ETL 파이프라인을 만들고, LLM 결과는 사람이 승인한 것만 반영했습니다."
**함께 알면 좋은 용어**: 구조화된 출력(Structured Output: LLM이 정해진 형식으로 답하게 하는 것), 환각(Hallucination)
