# 재사용 가이드 — 필드워드에서 가져다 쓸 것

- 작성일: 2026-11-11 · **고친 날: 2026-11-12** (새 카드 섞기, 발음 기호, 디자인 개편, 달력, 영어 낱말 발음표 — 맨 아래 "6. 바뀐 내용" 참고)
- 읽는 사람: **다른 학습 앱(예: 영어 학습 앱)을 만드는 세션.** 이 문서만 읽고 필요한 파일을 골라 가져가면 된다.

- 앱 주소: https://githubleejungah.github.io/field-words/

## 0. 한 줄 요약

필드워드는 **서버 없는 정적 사이트(HTML·CSS·순수 자바스크립트) + 로컬 관리 파이프라인(Python)**이고, 둘은 데이터 파일 하나로만 이어진다. 학습 규칙(`review.js`)과 음성 엔진(`speech`)은 화면과 떼어 두어서 **다른 앱에 거의 그대로 옮길 수 있다.**

## 1. 그대로 가져갈 것

### 1-1. 학습 규칙 모듈 — `site/js/review.js` (약 380줄, 화면 없음)

| 기능 | 함수 | 설명 |
|---|---|---|
| 5단계 상태 | `classify(confidence, correct)` | 확신도(확실/헷갈림/모름) × 정답 → 앎·불안한 앎·헷갈림·**착각**·모름 |
| 라이트너 상자 | `nextBox`, `intervalFor` | 상자 7개(1·2·4·7·15·30·60일) + 🏅 장기 기억(120일마다). 상자 4 이상에서 틀리면 두 칸만 내림 |
| 기록 | `record(id, {...})` | 복습 기록 저장 + 오늘 기록 + 날짜별 일지까지 한 번에 |
| 오늘 할 카드 | `plan(terms, {extra})` | 복습(급한 상태 순) + **새 카드 최소 30%**(`MIN_NEW_RATIO`, 10장이면 3장. 복습이 목표의 2배 넘게 밀리면 1장) + **섞어 내기**(`interleave`: 복습 2장마다 새 카드 1장). 밀려나는 복습은 가장 잘 아는 카드부터 |
| 확인 문제 | `makeQuiz(term, terms, pairs, rnd, force)` | 4지선다. 오답 보기는 혼동 쌍 → 같은 단계·등급 → 나머지 순 |
| 오늘의 마무리 | `planWrap`, `practice`, `markWrapped` | 착각·틀림 → 혼동 쌍 → 맞힌 것, **맞힐 카드로 끝냄**. 마무리 답은 복습 상자를 바꾸지 않음 |
| 성장 기록 | `getLog`, `ensureLog`, `stats` | 날짜별 일지(지우지 않음), 연속 공부일, 누적 그래프용 숫자, 단계별 진행 |
| 백업 | `exportAll`, `importAll` | 기록 전체를 JSON 파일로 저장·가져오기 |
| 설정 | `getSettings`, `setSettings` | 하루 목표, 화면 설정(예: 형광펜 모양 `hl`)을 같은 저장소에 |
| 시험용 | `useStore`, `useClock` | 가짜 저장소·가짜 날짜를 끼워 브라우저 없이 시험 |

- **옮기는 법**: 파일을 통째로 복사한다. 카드 데이터의 필수 칸은 `id`, `stage`, `level`, `definition`뿐이다(영어 앱이면 `stage`를 "주제"로, `definition`을 "뜻"으로 쓰면 된다).
- 저장 이름 앞머리 `PREFIX = "fw:v1:"`는 **앱마다 바꾼다**(같은 도메인에서 두 앱의 기록이 섞이지 않게).
- 시험: `tests/review.test.js`(20개)를 같이 가져가 `node --test tests/review.test.js`로 돌린다.

### 1-2. 음성 엔진 — `site/js/app.js`의 `speech` 객체와 도우미

영어 학습 앱에는 이 부분이 가장 중요하다. 브라우저 내장 음성(Web Speech API)만 쓰고 비용이 들지 않는다(ADR-0003).

| 기능 | 위치 | 설명 |
|---|---|---|
| 가장 좋은 음성 고르기 | `speech.voiceFor(lang)` | 이름 점수: Natural·Neural > Online > Google > Enhanced |
| 문장 단위 읽기 | `speech.start / run / sentences` | 긴 글을 문장으로 나눠 차례로 읽음(일부 브라우저가 15초 넘는 문장을 끊기 때문) |
| 재생 ↔ 일시정지 ↔ 이어 듣기 | `speech.toggle` | 휴대폰의 `pause()`가 불안정해서 **문장 번호를 기억해 직접 이어 읽음** |
| **휴대폰 고장 대비 4가지** | `speech.run`, `speech.unlock` | ① 고른 음성이 실패하면 기본 음성으로 다시 ② 끝 신호(onend)가 안 와도 감시 타이머로 다음 문장 ③ 아이폰 잠금 풀기(버튼 누를 때 빈 문장) ④ 말하기 전 `resume()` |
| 읽는 부분 색칠 | `speech.onSentence` + `highlight()` | 문장마다 `sec`(구역 이름)을 붙여 해당 구역 강조 |
| 기호 정리 | `speech.clean` | 괄호·화살표·가운뎃점을 음성이 어색하게 읽지 않게 |
| 한국어 숫자 | `koreanCounters` | "3번" → "세 번" |
| 낱말 고침표 | `SPEECH_FIXES` | 엔진이 잘못 읽는 한국어 낱말 교정(예: 어댑터 → "어댑 터") |
| 한국어 문장 속 영어 | `sayTermsInKorean`, `WORD_SAY` + `sayWordsInKorean` | 용어집의 영어 이름과 자주 나오는 영어 낱말(GitHub → 깃허브, PR → 피알 등)을 한국 현업 발음으로 바꿔 읽음. **앞뒤가 영어 글자면 바꾸지 않는다**(GitHub 안의 Git을 바꾸지 않게) |
| 약어 띄어 읽기 | `englishSay` | "PoC" → "P O C" (단어로 읽혀 "폭"이 되는 것 방지) |
| 진단 | `speech.lastError`, 정보 화면 `voiceInfo()` | 사용자가 "소리가 안 나요"라고 할 때 원인 확인 |

- **옮기는 법**: `speech` 객체 전체와 `koreanCounters`, `englishSay`를 복사한다. `t()`(문구 함수)와 `state.terms` 참조 부분만 새 앱에 맞게 바꾼다.
- 영어 앱에서 꼭 할 것: **문장마다 언어(`lang`)를 정해서** 넘긴다. 한국어 음성에 영어를 섞어 주면 제멋대로 읽는다(예: MoSCoW → "모스크바").

### 1-3. 이동 중 모드 — `app.js`

- 카드를 열면 전부 읽고 2초 뒤 다음 카드로 자동 이동.
- **화면 켜 두기**(Wake Lock API: `syncWakeLock`), **잠금 화면·이어폰 버튼**(Media Session API).
- 영어 듣기 연습(문장 듣기 → 잠깐 쉼 → 뜻)에 그대로 쓸 수 있다.

### 1-4. 화면 부품 — `app.js`

| 부품 | 함수 | 메모 |
|---|---|---|
| 안전한 요소 만들기 | `h(tag, props, ...children)` | 글자는 항상 `textContent`로 → XSS 방지 |
| 해시 라우팅 | `route()` | `#/term/아이디` 같은 주소로 화면 전환. 정적 호스팅에서 새로고침해도 안 깨짐 |
| 진행 링 | `progressRing(done, goal, size, labeled)` | 크기에 따라 굵기 자동, **그라데이션 + 그림자**로 입체감, `labeled`면 가운데 "5 / 10" 숫자 |
| 선 아이콘 | `ICONS`, `icon(name)`, `withIcon(name, text)` | 흔한 이모지 대신 직접 그린 24px 선 아이콘(눈·걷기·마이크·책·그래프·달·반짝임·검색·메달·화살표·ⓘ 등). 라이선스 걱정 없음, 글자색을 따라감 |

| 내 기록 화면 | `renderProgress`, `heatmap`, `growthHelp`, `growthChart`, `stageBars`, `backupSection` | 외부 라이브러리 없음. **공부한 날 달력**(달력 하나 + ‹ › 달 넘기기, 처음 공부한 달까지), 성장 그래프(요약 한 줄 + 범례의 ⓘ를 누르면 설명이 펼쳐짐, 세로축은 읽기 쉬운 눈금), 단계별 막대. 그래프 색은 색각 이상 검사 통과 값(`--chart-seen`, `--chart-long`) |
| 축하 효과 | `confetti`, `praiseTier` | 5장마다 칭찬 단계 상승, 화면 움직임 줄이기 설정 존중 |

| 의견 보내기 | `renderFeedback()` | Web3Forms(무료 월 250건) 또는 메일 앱. 스팸 막는 숨은 칸(honeypot). 보낸 뒤 **"보던 카드로 돌아가기"** 버튼 |
| 형광펜 | `mark.hl`, `highlightChooser()` | 핵심 문장(뜻)에 형광펜. **기본은 "글자 밑에 띠"**(글자와 겹치지 않아 눈이 편함), 정보 화면에서 "겹쳐 칠하기"로 바꿀 수 있음 |
| 더 하기 계산 | `moreExtra()` | "5장 더 하기"를 **오늘 실제로 한 장 수 기준**으로 계산(앱을 다시 열어도 버튼이 사라지지 않게) |

### 1-5. 디자인 규칙 — `site/css/style.css` (2026-11-12 개편)

사용자 의견("흐름이 없는 평면적 디자인, 흔한 이모지")을 받아 바꾼 규칙이다. 학습 앱이면 그대로 써도 좋다.

| 규칙 | 어떻게 |
|---|---|
| 배경 | 아주 연한 초록(`--bg: #f1f6f2`) + 흰 카드는 테두리 대신 옅은 그림자(`--shadow-1`) |
| 버튼 위계 | **주요**(`.btn.primary`: 진한 색 + 그림자 + 굵은 글자 + 화살표) > **보조**(`.btn.soft`: 연한 바탕 + 진한 글자) > 일반(`.btn`). 한 화면에 주요 버튼은 하나 |
| 시작 패널 | 연한 그라데이션 패널 + 큰 진행 링 + 주요 버튼 하나 |
| 정보 줄 | 개수 같은 정보는 버튼처럼 보이지 않게 조용한 글자 줄로. **색만으로 구분하지 않고 모양 표시**(● ◐ ○ ◆ 점선○) |
| 다른 화면 가기 | 버튼 줄에 섞지 않고 `.progress-row`(아이콘 상자 + 제목·설명 + ›)처럼 따로 |
| 형광펜 | 연한 세이지 띠, 글자 밑에(`body.hl-under mark.hl`) |
| 읽는 부분 색칠 | `.reading`은 둘레를 넓혀 색칠하므로, **위아래 줄과 색칠 폭보다 넓은 간격**을 둔다(단어 칸은 폭 8px, 간격 14~16px) |
| 이모지 | 쓰지 않는다. 1-4의 선 아이콘을 쓴다 |

## 3. 겪어 보고 배운 것 (같은 실수를 피하기)

1. **휴대폰에서 일찍 시험한다.** PC에서 되던 전체 듣기가 휴대폰에서 안 됐다(1-2의 고장 대비 4가지로 해결).
2. **카카오톡 안 브라우저에서는 소리·화면 켜 두기가 막힌다.** 처음부터 안내와 "크롬·사파리로 열기" 버튼을 넣는다. 공유 안내문에도 적는다.
3. **기록이 브라우저에만 있으면 날짜별 일지와 백업을 처음부터 만든다.** "오늘 기록"만 두면 지난날을 볼 수 없다. 나중에 만들면 이력에서 되살리는 작업이 필요하다.
4. **듣기는 기록하지 않는다.** 기억에 남는 것은 스스로 떠올리는 순간이다. 듣기만 한 것을 "외웠다"로 치면 복습이 늦어진다.
5. **같은 날 두 번 맞혔다고 복습 간격을 두 번 늘리지 않는다.** 마무리·재도전은 연습으로만 기록한다.
6. **새 항목은 먼저 배우고 몇 장 뒤에 묻는다.** 처음 보는 것을 바로 시험하면 찍게 되고 기분만 나빠진다.
7. **틀렸을 때 빨간 X를 쓰지 않는다.** 내 답과 정답을 나란히 보여 주고, 확신하고 틀린 "착각"은 찾아낸 것 자체를 칭찬한다.
8. **음성 엔진은 기기마다 다르다.** 잘못 읽는 낱말은 고침표에 한 줄씩 추가한다. 발음 칸(`read_as`: 글자로/단어로, `tts`: 음성용 표기)을 데이터에 둔다.
9. **셸로 코드 조각을 넣을 때 정규식의 `\`가 사라질 수 있다.** 그래서 배포 검사에 `node --check`(문법 검사)를 넣었다.
10. **오래된 아이폰은 정규식 "뒤를 보는 검사"(`(?<=...)`)를 모른다.** 앱 전체가 안 뜰 수 있으니 쓰지 않는다.
11. **복습만 계속 내면 지루해서 그만둔다.** 간격 효과로는 복습 먼저가 맞지만, 새 카드를 일정 비율 섞어야 동기가 유지된다(사용자 의견 2026-11-12).
12. **화면에만 있는 값은 앱을 다시 열면 사라진다.** "오늘 몇 장 더 하기로 했는지"를 메모리에만 두었다가 버튼이 사라졌다. 계산은 저장된 기록(오늘 한 장 수)을 기준으로 한다.
13. **한국어 음성에 영어 낱말을 그대로 주면 엉뚱하게 읽는다**(GitHub → "깃써브"). 데이터 속 영어 낱말을 한 번 전부 뽑아 보고 발음표를 만든다. 바꿀 때는 낱말 경계를 지킨다.
14. **발음은 두 가지를 함께 보여 준다.** 발음 기호(IPA)는 영어 소리, 한글은 현업에서 읽는 방식(PoC = 피오씨). 약어와 현업식 읽기는 발음 기호로 나타낼 수 없다.
15. **사용자가 고르기 어려운 디자인은 둘 다 만들어 직접 써 보게 한다.** 형광펜 모양을 설정으로 넣어 비교하게 했고, 사용자가 "글자 밑에 띠"를 골랐다.
16. **그래프에는 읽는 법이 필요하다.** 요약 한 줄은 늘 보이게, 자세한 설명은 ⓘ 안에 접어 화면을 깔끔하게.
17. **달력은 월이 분명해야 한다.** 주 단위 잔디는 월 구분이 어렵다. 달력 하나 + 달 넘기기가 휴대폰에서 가장 깔끔했다.
18. **GitHub Pages 배포는 가끔 GitHub 쪽 오류로 실패한다**("No artifacts named github-pages"). 검사가 통과했다면 빈 커밋으로 다시 실행하면 된다.

## 4. 영어 학습 앱에서 바꿔야 할 것 (제안)

- 데이터 칸: `term_en`/`term_ko` → `text`(영어 문장·단어), `meaning`(뜻), `ipa`(발음 기호), `audio_lang: "en-US"`. 필드워드의 `pronunciation.ipa`와 `termTitle()` 표시 방식을 그대로 쓸 수 있다.
- 새 카드 비율(`MIN_NEW_RATIO`)은 영어 단어처럼 양이 많은 앱이면 0.3~0.4가 적당하다. 섞어 내기(`interleave`)는 그대로.
- 퀴즈: 뜻 고르기 외에 **듣고 고르기**(음성만 들려주고 뜻 고르기), **빈칸 채우기**(예문에서 단어 빼기).
- 말하기 연습: 브라우저 음성 인식(SpeechRecognition)은 기기·브라우저마다 지원이 달라서, 처음에는 필드워드처럼 **"스스로 채점(맞음/일부/아직)"**으로 시작하는 것을 추천.
- 저장 이름 앞머리(`fw:v1:`)를 새 앱 이름으로 바꾼다.

## 5. 가져가지 말아야 할 것

- `private/` 폴더(개인 면접 준비 문서)는 저장소에 없고, 가져가지 않는다.
