# ADR-0007: 용어 후보는 `pipeline/candidates/` 한 곳에 모은다

- 상태(Status): **채택(Accepted)** — 2026-11-27 사용자 지시("한 곳으로 만들어 주세요. 새로 만든 곳 말고 기존에 있던 곳으로요").
- 날짜: 2026-11-27
- 결정한 사람: 프로젝트 오너(사용자). Claude가 두 곳의 생성일과 쓰임을 조사해 보고.
- 대체(Supersedes): 없음. ADR-0005의 배경에 나오는 `field-words-inbox` 이슈는 이 ADR부터 쓰지 않는다(ADR-0005의 결정 자체는 그대로).

## 1. 배경 (Context)
- 용어 후보를 모으는 곳이 두 군데였다.
  - `pipeline/candidates/` — 2026-11-10 설계 때부터 있던 곳. architecture · data-model · flows · 운영 자동화 문서가 모두 이곳을 "승인 전 후보"의 자리로 적는다. Git 밖(`.gitignore`)이다.
  - GitHub 비공개 저장소 `githubleejungah/field-words-inbox` — 2026-11-15에 만든 이슈 수집함. 다른 저장소 세션이 후보를 올리는 곳으로 썼다(이슈 1~5번).
- 두 곳에 같은 후보가 겹쳐 있었다(이슈 2번 = `2026-11-21_강의_용어후보.md`, 이슈 5번 = `2026-11-27_강의_용어후보.md`). 몇 개를 넣어야 하는지 세려면 두 곳을 다 봐야 했다.
- 두 Claude 계정은 같은 PC의 같은 폴더(`C:\Users\User\실습산출물\field-words`)에서 일한다. 그래서 Git 밖 폴더도 두 계정이 함께 볼 수 있다.

## 2. 결정 (Decision)
**용어 후보는 `pipeline/candidates/` 한 곳에만 둔다. `field-words-inbox`에는 더 올리지 않는다.**
- 인박스 이슈 1~5번의 후보 줄은 내용 그대로 이 폴더의 `.md` 파일로 옮겼다. 이슈는 닫고, 인박스 README 맨 위에 "쓰지 않음"을 적었다. 저장소 자체는 지우지 않는다(기록 보존).
- 어느 세션이든 새 후보가 나오면:
  1. 중복부터 확인한다 — `site/data/glossary.json`(id · 영어 이름 · **별칭**)과 이 폴더의 모든 후보 파일.
  2. 세션마다 `pipeline/candidates/날짜_주제_용어후보.md` 파일 1개를 만든다. 한 줄 형식은 그대로 쓴다:
     ``- [ ] `id` English / 한국어: 나온 상황 한 줄 (짝: 헷갈리는 용어)``
  3. `00_후보_목록.md`(한 장 목록)의 개수와 표를 함께 고친다.
- 다듬기(정의 · 예문 · 면접 답변)는 지금처럼 `pipeline/candidates/날짜.py` → `preview.py` → 사람 승인 → `promote.py` 순서다.
- 지킬 것은 인박스 때와 같다: 강의 문장을 그대로 옮기지 않는다. 비밀값과 실제 개인정보를 쓰지 않는다.

## 3. 대안 (Alternatives)
| 대안 | 버린 이유 |
|---|---|
| 인박스 하나로 합치기 | 사용자가 "기존에 있던 곳"을 골랐다. 인박스는 나중(11/15)에 생겼고, 설계 문서와 파이프라인 명령은 모두 `candidates/`를 기준으로 한다 |
| 두 곳 유지 + 동기화 | 같은 후보를 두 번 세고 두 번 고치게 된다. 지금 문제의 원인이다 |
| 후보를 공개 저장소에 커밋 | 승인 전 후보는 공개하지 않는다는 기존 원칙(data-model 6 · 15번 행)과 어긋난다 |

## 4. 결과 (Consequences)
### 좋아지는 점
- "몇 개 남았나"를 `00_후보_목록.md` 한 파일로 본다(2026-11-27 기준 318개).
- 다듬는 세션이 이슈와 폴더를 오가지 않는다. 후보 파일 바로 옆에서 시드 파일을 만든다.

### 감수하는 점
- 후보는 Git 밖이라 이 PC에만 있다. PC를 바꾸거나 폴더를 지우면 사라진다. 중요한 묶음은 `seeds/`로 승격되면서 Git에 남는다.
- 클라우드 세션이나 다른 PC 세션은 이 폴더에 직접 쓸 수 없다. 그때는 대화 결과로 후보 줄을 받아 이 PC 세션이 파일로 옮긴다.
- 두 계정이 같은 후보 파일을 동시에 고치지 않도록, 세션마다 새 파일을 만들고 남의 파일은 읽기만 한다.
