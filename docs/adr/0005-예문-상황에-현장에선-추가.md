# ADR-0005: 예문 상황에 "현장에선"(`field`)을 추가한다

- 상태(Status): **채택(Accepted)**
- 날짜: 2026-11-16
- 결정한 사람: 프로젝트 오너(사용자). 리테일 챗봇 실습 용어 후보(field-words-inbox 이슈 1번)를 다듬으며 "나온 상황 한 줄을 '현장에선' 예시로 써 달라"고 요청하고, 두 안 중 새 상황 추가를 골랐다.

## 1. 배경 (Context)
- 예문 상황(`examples[].context`)은 `meeting`(업무 회의) · `interview`(면접 답변) · `review`(문서·코드 리뷰) 세 값뿐이었다.
- 세 상황은 "현업에서 이렇게 말한다"를 연습하는 **꾸며 쓴 문장**이다.
- 실습·작업 중에 용어를 **실제로 만난 장면**이 쌓이고 있다. 예: "채팅 TIMEOUT 원인을 찾다가 안쪽 제한이 바깥보다 짧아야 한다를 정리했다".
- 이런 장면은 기억에 오래 남는 재료지만, 넣을 칸이 없었다.

## 2. 결정 (Decision)
**예문 상황 열거형에 `field`를 추가하고, 화면에는 "현장에선"으로 보인다.**
- `field`는 선택이다. 실제 겪은 일이 있을 때만 쓴다. 꾸며 쓰지 않는다.
- 문장 앞에 겪은 곳을 쓴다(예: "리테일 챗봇 실습에서"). `sources`에도 같은 출처를 적는다.
- 한 카드에 `field`는 하나만 둔다(같은 상황 예문 중복 금지 규칙 그대로).
- 스키마 버전은 `1.0 → 1.1`. 열거형 값 추가를 칸 추가와 같은 급으로 본다.
- 바꾼 곳: `schema/glossary.schema.json`, `site/i18n/ko.json`(`context.field`), `pipeline/preview.py`, `site/data/glossary.json`의 `schema_version`.
- 화면 코드(`app.js`)는 고치지 않는다. 예문 이름을 이미 `context.<값>` 문구에서 가져오고, 듣기 모드도 같은 문구를 읽는다.

## 3. 대안 (Alternatives)
| 대안 | 버린 이유 |
|---|---|
| 실제 겪은 일을 `interview`(면접 답변)로 쓰기 | 구조는 그대로지만 "면접 답변" 이름 아래 실습 장면이 붙어 어색하다. 연습용 문장과 실제 장면이 섞여 구분되지 않는다 |
| 카드에 별도 칸(예: `field_note`) 추가 | 화면 코드와 듣기 흐름을 새로 고쳐야 한다. 예문과 같은 모양(상황 + 한 줄)이라 예문 목록에 두는 편이 단순하다 |

## 4. 결과 (Consequences)
### 좋아지는 점
- 실습에서 만난 장면을 그대로 학습 재료로 쓴다("기획 과정·화면 자체도 학습 재료" 원칙과 맞다).
- 같은 용어를 다시 만나면 새 카드 대신 현장 예시와 출처만 더하면 된다.

### 감수하는 점
- 현장 예시는 겪은 사람의 맥락(포트 번호, 모델 이름)이 들어가 수강생에게 낯설 수 있다. 문장 하나로 이해되게 풀어 쓴다.
- 이미 공개된 카드에는 아직 현장 예시가 없다. 새로 겪을 때마다 채운다.

## 5. 다시 검토할 조건
- 현장 예시가 늘어 한 카드에 여러 장면을 보여 주고 싶어질 때(지금은 카드당 하나)
- 수강생 의견에서 "현장에선" 예시가 헷갈린다는 말이 여러 번 나올 때
