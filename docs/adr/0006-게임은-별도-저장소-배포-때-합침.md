# ADR-0006: 게임은 별도 저장소를 정본으로 두고, 배포할 때 `/game/`으로 합친다

- 상태(Status): **채택(Accepted)** — 2026-11-26 설계 문서(architecture 3-2 · data-model 정본 표 · flows 9절)와 함께 사용자 승인("설계 승인"). 근거는 `docs/requirements-game.md`.
- 날짜: 2026-11-26
- 결정한 사람: 프로젝트 오너(사용자)가 B안을 골랐다("이어서 b안으로 시작합니다"). Claude가 구조를 제안.

## 1. 배경 (Context)
- 코드 가려 보기 게임은 별도 저장소 `field-words-3d-lab`에서 만든다. 2026-11-25에 공개로 바꾸고 따로 GitHub Pages에 올렸고, 필드워드 맨 아래에 링크를 달았다(A안).
- 사용자는 두 앱을 **한 주소**에서 보고 싶어 한다. 동시에 게임(파이썬 연습 포함)은 별도 세션에서 **계속 개발**한다.
- 게임은 파이썬 실행기(Pyodide)를 jsDelivr에서 동의한 뒤에만 받는다(게임 ADR-0007). 필드워드는 "외부 스크립트 0개" 원칙이 있다(architecture 5절, `check_all.py` 7번).
- 출처(origin)는 이미 `https://githubleejungah.github.io` 하나다. 두 앱의 localStorage는 지금도 같은 곳에 있고 접두어(`fw:v1:` · `cm:v1:`)로 나뉜다.

## 2. 결정 (Decision)
**게임 저장소가 게임 코드의 정본이다. 필드워드 배포 작업이 배포할 때마다 게임 `main`을 받아 검사한 뒤 `site/game/` 자리에 넣어 한 묶음으로 올린다.**
- 주소: 필드워드 `/field-words/`, 게임 `/field-words/game/`.
- 필드워드 저장소에는 게임 파일을 커밋하지 않는다(사본은 배포 묶음에만 생긴다).
- 배포 시점: 필드워드 `main`에 올릴 때 · 하루 1번(한국 06:00) · 손으로 실행. 게임만 고친 날도 다음 아침에 반영된다.
- 검사: 필드워드 검사에 더해 게임 검사 4가지(공개 점검 · 문제 검사 · 단위 시험 · 문법 검사)를 돌린다. 게임의 문제 검사는 필드워드 사전을 같은 작업 안에서 찾을 수 있어 건너뛰지 않는다.
- 실패하면: 필드워드 검사나 게임 검사가 하나라도 실패하면 배포 전체를 멈춘다. 지난 사이트(게임 포함)가 그대로 남는다(요구 Q6 · AC-110).
- 외부 스크립트 예외: `/game/` 아래, 사용자가 동의한 뒤, 버전 고정 Pyodide 1개만. 필드워드 화면은 계속 0개다. 실행기는 Web Worker 안에서만 돌아 localStorage에 접근하지 못한다.
- 합친 주소가 휴대폰에서 확인되면 게임 저장소의 따로 된 Pages는 끈다(주소 하나로).

## 3. 대안 (Alternatives)
| 대안 | 버린 이유 |
|---|---|
| A. 한 번 옮기기(게임 파일을 필드워드 저장소에 복사하고 게임 저장소는 닫기) | 게임을 별도 세션에서 계속 개발하려는 사용자 뜻과 맞지 않는다 |
| C. Git 서브모듈 | 명령이 어렵고 커밋 번호를 손으로 올려야 해 실수하기 쉽다. 배우는 사용자에게 부담이 크다 |
| 링크만 두기(2026-11-25 A안 유지) | 주소가 둘이다. 사용자가 한 주소를 원했다 |

## 4. 결과 (Consequences)
### 좋아지는 점
- 주소 하나로 두 앱을 쓴다. 게임은 지금처럼 따로 개발하고, 다음 배포 때 저절로 들어온다.
- 필드워드 저장소가 무거워지지 않는다(게임 파일 · 파이썬 실행기 모두 저장소 밖).
- 게임 기록과 이미 받아 둔 파이썬 실행기 캐시가 그대로 이어진다(출처가 같다).

### 감수하는 점
- 게임 `main`이 깨지면 그날 필드워드 수정도 올라가지 않는다(Q6에서 감수하기로 함). 게임을 고치거나 손으로 다시 실행하면 풀린다.
- 게임만 고치면 최대 하루 늦게 반영된다. 급하면 손으로 실행한다.
- 필드워드 배포 시간이 게임 검사만큼 길어진다(게임 배포 기록 기준 검사 약 1분 23초, 2026-11-25 관찰).

## 5. 다시 검토할 조건
- 게임 개발이 끝나 더 이상 따로 개발할 일이 없을 때 → A(한 번 옮기기)로 단순하게.
- 게임이 jsDelivr 말고 다른 외부 서버를 더 쓰게 될 때 → 외부 스크립트 예외를 다시 본다.
- 하루 늦은 반영이 불편해질 때 → 게임 저장소가 필드워드 배포를 깨우는 방법(비밀 키 필요)을 새 ADR로 본다.
