# 요구 — 게임을 필드워드 주소에서 함께 보기 (B안: 배포할 때 합치기)

> 상태: 설계 승인(2026-11-26 "설계 승인") · 구현 중
> 검사: `python doc_lint.py ears docs/requirements-game.md --strict`
> 필드워드의 기존 결정(로그인 없음 · 서버 없음 · 비용 0원 · 학습 기록은 브라우저에만)은 그대로 따른다. 이 문서는 게임을 합치는 일에서 새로 정할 것만 다룬다.
> 게임 자체의 요구(문제 · 탑 · 파이썬 연습)는 게임 저장소 `field-words-3d-lab/docs/requirements.md`가 정본이다. 여기서 다시 쓰지 않는다.

## 1. 원문 (사용자 문장, 고치지 않음)

> 게임 연결은 A안으로 정했어: 게임 저장소를 공개로 바꾸고 GitHub Pages로 배포한 뒤, 필드워드 메뉴에 게임 링크를 달아 줘.

> 두 가지를 한개의 주소에서 볼 수 없나요?

> 게임세션에서 계속 추후 개발하면 그 후에 붙일 땐 어떻게 해요?

> 파이썬도 개발할건데 b로 했을 때 문제는 없어요?

> 그럼 파이썬 돌릴 때 처음 느려지는 건 같죠? 이 대답만 듣고 이어서 b안으로 시작합니다.

(2026-11-25 ~ 11-26. 첫 문장의 "A안"은 링크만 다는 방법으로, 2026-11-25에 끝냈다. 이 문서는 그 뒤에 고른 B안을 다룬다.)

## 2. 인터뷰 (Q/A)

진행: 질문 1개씩 → 사용자 답. "추천 수용"은 Claude 추천을 받아들인 것.

Q1: 한 주소로 만드는 방법은? (구조)
A1: B안. 게임 저장소를 정본으로 두고, 필드워드 배포 작업이 배포할 때 게임 저장소의 `site/`를 받아 `site/game/` 자리에 넣어 함께 올린다. 필드워드 저장소에는 게임 파일 복사본을 두지 않는다. 이유: 게임을 별도 세션에서 계속 개발하면서도 주소는 하나로 쓴다. (추천 수용, 2026-11-26. 버린 안: A 한 번 옮기기 — 별도 개발이 끝남, C 서브모듈 — 명령이 어렵다)

Q2: 게임을 고치면 필드워드 주소에 언제 반영되나? (성능 · 사람 개입)
A2: 필드워드가 배포될 때마다 그때의 게임 `main`이 들어간다. 필드워드에 올릴 것이 없는 날도 반영되도록 하루 1번 자동 배포와 손으로 실행 버튼을 둔다. 게임 저장소가 필드워드 배포를 바로 깨우는 방법은 비밀 키(토큰)가 필요해 넣지 않는다. (추천 수용, 2026-11-26)

Q3: 파이썬 실행기(Pyodide, 외부 jsDelivr)는? (데이터 출처 · 개인정보 · 규제)
A3: 게임 ADR-0007을 그대로 따른다(동의한 뒤에만, 버전 고정, Web Worker 안에서만). 필드워드의 "외부 스크립트 0개" 원칙은 필드워드 화면에는 그대로 두고, `/game/` 아래 이 실행기 1개만 예외로 ADR에 적는다. 출처(origin)는 지금도 `githubleejungah.github.io` 하나라 합쳐도 새 위험은 없다. (추천 수용, 2026-11-26)

Q4: 파이썬을 처음 돌릴 때 느린 정도는? (성능)
A4: 합치기 전과 같다. 실행기는 어느 쪽이든 jsDelivr에서 받는다(압축 약 6.2MB, 게임 ADR-0007). 두 번째부터는 브라우저 캐시를 쓴다. (사용자 질문에 대한 답, 2026-11-26)

Q5: 게임 기록은? (데이터)
A5: 게임 기록(`cm:v1:*`)과 필드워드 기록(`fw:v1:*`)은 같은 출처의 localStorage에 접두어로 나뉘어 그대로 있다. 합쳐도 옮기거나 바꾸지 않는다. 지금까지 쌓인 게임 기록도 이어진다. (관찰 O: 출처는 주소 경로와 상관없다)

Q6: 게임 검사가 실패하면? (실패 동작)
보기: A 배포 전체를 멈춘다(지난 사이트가 그대로 남음, 필드워드 수정도 그날은 못 올림) · B 게임만 빼고 필드워드를 올린다(그동안 `/game/`이 비어 링크가 404) · C 마지막으로 통과한 게임 커밋을 대신 넣는다(통과한 커밋 기록을 따로 관리해야 함).
A6: A. 배포 전체를 멈춘다. 이유: 틀린 게임이 수강생에게 나가지 않고, 지난 사이트(게임 포함)가 그대로 살아 있어 학습자 화면은 깨지지 않는다. 막히면 실패 알림 메일이 오고 원인이 Actions 기록에 남는다. B는 링크가 깨지고, C는 구조가 복잡해진다. (추천 수용, 2026-11-26)

필드워드에서 그대로 이어받는 칸(새로 묻지 않음): 사용자 · 권한(누구나, 로그인 없음) · 비용(0원, GitHub Actions 공개 저장소 무료) · 규제(개인정보를 모으지 않음).

## 4. 수용 기준 (EARS)

- 한 행 = 요구 1개 = 시험 1개 후보.
- 패턴: U 항상 · E When(하면) · S While(동안) · O Where(경우) · W If…then(만약).
- 분류: SFR 기능 · DAR 데이터 · PER 성능 · SECR 보안 · CONR 제약.
- ID: AC-101부터 쓴다(AI 답 검수 AC-01~19와 겹치지 않게).`n- 근거: `Qn` 인터뷰 답 · `O` 관찰(기존 코드 · 문서) · `I` 추론 · `GAS-n` 가정.
